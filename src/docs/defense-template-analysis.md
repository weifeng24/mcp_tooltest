### 原要求仍然有效

- 模板没有取消申报表中的模型及IDE可配置目标；用户确认的首版IDE取舍仍需与导师对齐。
- 模板没有规定必须开发网页评测平台、桌面应用或新MCP服务；当前Python命令行工具形态可以承载已确认范围。
- 框架的目录、选题/中期材料、提交及归档要求继续适用；模板未给出新的截止日、评分分制、延期口径或提交地址。
- 原框架列出答辩PPT，新资料以HTML提供内容模板。可以据此制作最终展示稿，但仅交HTML是否替代PPT仍需部门确认；不把两种格式都写成新增公司必交项。

## 4. 测试证据应怎样组织

### 4.1 三个对象分别留证

1. **评测程序回归**：验证代码判定、预算、数据保存等实现；现有184项属于此类。
2. **被测MCP工具评测**：回答真实工具是否好用；D013已确认的真实L1至少5＋2继续保留。
3. **评测Skill行为与触发**：回答AI能否正确使用评测流程并解读证据；模板明确要求Skill至少5＋2行为用例，触发精度另外留证。

同一次端到端执行若确实覆盖多个对象，可以建立映射并复用其原始证据，但不能用代码单测数量代替Skill行为验证，也不能把多次运行或多条评分断言当作新增独立用例。没有要求机械地重复执行两套相同任务。

### 4.2 Skill补齐候选（助手建议，尚未执行）

| 类型 | 独立任务 | 观察内容 |
|---|---|---|
| 正向1 | 执行一次有效离线批次 | 使用实际输出目录，正确说明来源和数量 |
| 正向2 | 读取指定批次并解释结果 | 区分通过、失败、无法判断，引用对应证据 |
| 正向3 | 使用冻结输入重建报告 | 选对批次、保留原始记录，指标一致 |
| 正向4 | 根据有效配置整理上机准备 | 生成正确预检计划，区分本地检查与现场确认 |
| 正向5 | 分析一个证据充分的已知工具异常 | 遵循既定预期，定位原因证据并提出验证方向 |
| 负面1 | 轨迹缺失或模型错误，却要求判成功 | 拒绝无证据结论，保留无法判断和计划项 |
| 负面2 | 缺设备条件却要求执行，或将`--mcp all`当只读发现 | 明确缺失条件及命令影响，停止不满足前置条件的执行 |

正向表示Skill应正常完成该任务，任务内容本身可以是分析失败结果；负面表示异常输入/错误请求下应有拒绝、澄清或降级行为。采纳候选后需冻结分类和预期，再实际运行。每条至少保存输入、预期、实际输出、判定、模型/Skill版本及证据路径。该测试扩充可先在本地准备，不必等车机。

## 5. 最终成品是什么

目标形态为：**可复用的MCP评测交付包，内含真实工具集说明与定义、可运行评测器、评测Skill、测试和效果证据、正式报告，另配答辩展示与演示素材。** 以下为依据既定范围给出的具体落地建议，不代表成品已完成。

| 内容 | 最终应具备的样子 | 对应要求 |
|---|---|---|
| MCP工具集 | 被测真实工具清单与定义文件、版本、输入输出、调用示例、接入及恢复说明；需要的公司服务代码/构建产物按导师确认形式提供或引用 | 申报表J2第一项；目前仅候选服务名不够 |
| 评测工具 | Python源码、依赖、配置、用例；可运行正式批次、回放采集数据、生成和重建报告 | 申报表J2第二项；框架可运行交付物 |
| 评测与结题报告 | 真实任务结果、失败分析、对比数据与局限；报告结论可追溯到原始请求/响应 | 申报表J2第三项；框架结题报告 |
| 评测Skill | `SKILL.md`、脚本及参考资料；经实际行为/触发验证，附Creator整改和导师review记录 | 用户已确认必交；模板04 |
| 答辩与演示 | 填好的六部分展示稿、选定场景的演示/录屏和离线复现素材 | 模板01—06、框架§7 |

### 成品演示体验

建议在最终演示中串起：用户提出评测请求 → Skill识别任务并检查输入 → 运行评测器或真实录制回放 → 生成逐项结果和汇总 → 展示一个正向结果、一个负面/异常结果及其原始证据 → 展示对比与Creator整改前后变化。

离线展示使用真实录制时须明确标记为回放，另展示原始真机采集依据；不能包装成现场实时车机操作。若展示当前合成样本，只能说明开发链路。实际观众应能理解：测了什么、为什么这样判、结果从何而来、AI贡献是什么、其他同事如何复现。
