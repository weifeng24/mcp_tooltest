# 15分钟讲解提纲与问答准备

本稿为演练提纲；个人实践、导师反馈和真实业务成绩须由实际记录补齐。

## 0—2分钟：个人、来源与目标

简述姓名、部门、导师和课题来源。说明交付是工具集、评测器、报告及Skill；目标是让工具调用与判定有可复核证据。介绍设备机会有限的已确认条件，并说明真实业务基线尚待采集。个人贡献按本人实际操作填写，不照抄未经经历的工作叙述。

## 2—7分钟：方案与AI运用（含Skill）

沿展示图解释配置、固定计划、设备/回放、判定和报告。用一个例子说明执行成功和业务通过不同，缺证据不能当成功。说明AI在开发、Skill流程以及L2模型决策中的不同作用；真实模型＋mock不能证明车机能力。

Skill采用Tool Wrapper，操作步骤低自由度、解释中等自由度。展示当前7场景实际输出与评分，解释35是评分项数、不是35个独立案例。说明35/35与32/35的局限，尤其共享上下文、无耗时信息、额外批次来源未核实和基线配置过程证据缺口。培训A/B/C/D需原文后填写。

## 7—12分钟：演示

1. 打开离线记录页，先指明synthetic、已执行记录回看、无真实设备。
2. 查看帮助及预检，说明executed=0不等于已完成工具调用。
3. 展示本机8项合成回放通过，打开一个原始批次报告和证据。
4. 展示构造越界响应返回成功时，判定器输出1项fail。解释它是本地反例，不能称真实车机缺陷。
5. 展示重建后summary一致，解释它不重新调用工具。
6. 真实资料具备后，将主演示替换为真实批次/录屏，合成例子保留用于说明判定机制。

无旁白WebM约35秒，可作为流程概览；完整5分钟演示应结合实际报告和解释。断网时使用本地HTML、原始文件和视频；缺证据不切换旧成功报告冒充本次结果。

## 12—15分钟：数据、收获与限制

区分程序184项回归、Skill7场景与尚未完成的真实5＋2。介绍已准备的人工/Skill辅助对比方案，未采集时间不报改善比例。技术例子可用非有限值拦截和异常决策保留；个人收获和导师协作实例由本人补充。结束时明确下一步真实采集、触发验证、导师review及提交。

## 问答准备

| 可能问题 | 回答要点 |
|---|---|
| 测试全绿为什么还会发现问题？ | 原测试没有覆盖特定反例；应保存失败输入、修复和回归，而不以数量代替完整性 |
| 为什么用例失败也可能有价值？ | 被测工具确实违反冻结契约时，可靠地发现失败就是评测产出；不能倒改预期 |
| 回放与真机有什么区别？ | 回放消费既有记录，不证明当前设备在线或状态变化；需要原始真实采集依据 |
| Skill相对普通AI提升多少？ | 仅有本轮有限流程差异；不是盲评，没有效率/稳定增益证据 |
| 为什么缺失结果不能删？ | 分母来自预先冻结的计划，缺失应保留无法判断，删除会抬高通过率 |
| 为什么还没写A/B/C/D？ | 缺培训定义原文，不用通用猜测替代公司分类；已明确待补材料 |
| 模型和IDE是否都支持？ | L2循环已有离线实现，真实双模型和IDE评测未完成；首版IDE范围差异仍需确认 |
| 自动触发是否通过？ | 未通过真实自动触发验证；已准备20查询和环境检查，缺CLI/授权条件 |
