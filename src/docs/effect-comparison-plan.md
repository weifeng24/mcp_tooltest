# 业务基线与效果对比实验方案

状态：2026-10-23本地方案已完成；真实业务基线、人工耗时、设备效果均未采集。以下样本量和流程是本项目建议安排，不是公司另行规定的阈值。

## 1. 问题、对象与当前证据

课题目标是评测真实车载MCP工具是否好用。拟验证的工程问题为：工具定义、执行日志和判定依据能否被统一组织，使同事可检查和复现结果。部门当前是否存在重复整理、平均耗时及错误率，需要真实使用者确认；设备只有1—2次机会的约束来自用户确认，不能替代业务痛点访谈。

分别报告三类结论：评测程序的实现质量、Skill执行流程质量、真实被测工具的效果。已有184项软件回归和iteration-6的7场景行为结果不能当作真实工具可用性或人工提效数据。

## 2. 优先对比：相同证据的人工整理与Skill辅助整理

此实验可在取得一组可用资料后先做离线阶段；合成资料的实验只支持合成条件下结论，真实录制到位后再开展真实数据批次。

| 控制项 | 预先固定的安排 |
|---|---|
| 输入 | 同一工具定义版本、同一批请求/响应与计划、相同判据；保留原始哈希 |
| A组 | 用户/同事按约定手工流程完成统计、失败归类和报告；写明可用工具，不能预设原来只用记事本 |
| B组 | 在相同输入和任务上使用冻结Skill＋评测器完成相同交付内容 |
| 标准答案 | 在评分前由工具维护者/确认人根据规范冻结；不让被测模型自己生成后自行证明 |
| 任务量 | 建议至少5个独立报告整理/分析任务，含异常和缺证据；能否扩大根据实际时间确认 |
| 顺序效应 | 相似难度配对任务交替A/B顺序；同一人重复同一输入须记录学习效应，不能称完全独立 |
| 质量评分 | 预先检查计划分母、判定/失败类别、证据引用、来源与局限；报告输出达到相同完整性标准 |
| 计时 | 分别记录人工主动操作时间、工具等待时间、返工时间和总墙钟时间；明确开始/结束点 |
| 缺失与失败 | 保留失败任务、超时及缺测；缺失时间记null，不补0，不事后剔除困难任务 |

耗时改善按配对任务计算`(A时间-B时间)/A时间`；A为0或未知时不计算。优先同时展示原始秒数、样本数、中位数及范围，样本少时不作显著性或泛化结论。月度节省工时仅在业务月频次由用户确认后估算，并标明假设，不先填模板XXh。

## 3. 真实工具接口评测

按[case-freeze.md](case-freeze.md)冻结至少5正向＋2负面，记录设备/工具版本、预期来源、原状态及恢复；与Skill行为用例区分。所有结果均保留计划项：

- 计划内通过率：通过数／全部计划项。
- 判定覆盖率：（通过＋失败）／全部计划项。
- 已判定项通过率：通过／（通过＋失败），单独列出，不替代前两项。
- 时延按成功/失败/无法判断分组，未知值不计为0。
- 真实失败用例是评测发现，不能通过倒改规范消除失败。

如果有真实版本改进，采用相同任务/环境的前后批次；没有改进版本时只报告现状和缺陷，不制造“改进后”数据。

## 4. 条件允许的L2对比

真实工具定义、模型接入和L1稳定后，可选择“相同模型下工具描述改进前后”或“两种已验证模型”之一。固定任务、工具范围、预算、温度等配置；只改变声明变量。保留模型版本、逐轮调用、执行结果、最终回答、用量缺失项及重复次数。

DeepSeek真实模型＋mock的历史结果只能解释该模拟条件；Kimi权益和端点未核实。模型切换实验不证明IDE/客户端适配。

## 5. 记录表与完成判据

采集模板：[comparison-records-template.json](comparison-records-template.json)。所有null字段为未采集，不是零值；实际实验另存新文件，模板不直接计为结果。

完成条件：实验前冻结输入/判据；实际A/B记录完整；每个数值有原始计时或执行证据；独立复核质量；报告失败与局限；得到业务使用者反馈。当前仅方案、字段与统计口径完成。
