# 评测报告解读指南

报告位置：`tests/results/<run-id>/report.md`（由 `summary.json` 与 `results.jsonl` 重建，可复现）。

## 分组口径

分组键为 `通道|层次|类别|模型`，例如 `device|L1|positive|-`：

| 段 | 取值 | 含义 |
|---|---|---|
| 通道 | device / replay | 真机执行 / 离线回放。**只有 device 可作结论** |
| 层次 | L1 / L2 | 接口级 / 模型级 |
| 类别 | positive / negative / edge | 正向 / 负面控制 / 边界 |
| 模型 | 配置 id 或 - | L2 按模型分组；L1 为 - |

## 指标含义

| 指标 | 定义 | 解读 |
|---|---|---|
| 计划内通过率 | P / N（含未执行） | 保守口径；未执行计入分母 |
| 判定覆盖率 | (P + F) / N | 证据充分度；过低说明大量 unassessed，先查证据链 |
| 已判定通过率 | P / (P + F) | 辅助参考，不能脱离覆盖率单独引用 |

## verdict 语义

- `pass`：全部断言通过。
- `fail`：断言失败或跟踪完整但超时未完成。负面用例 fail 且原因为"预期错误未出现"是**被测服务端未落实约束的评测发现**，应写入报告正文。
- `unassessed`：证据不足（基础设施错误、录制缺失、需人工复核）。**不是失败也不是通过**；引用结论前先看 unassessed 占比。

## 引用规范

引用任何数字时给出：run_id、通道、分组、分母（如"device 通道 L1 正向 5/5 通过（run: l1-device）"）。禁止引用 replay 通道数字作为工具能力结论。
