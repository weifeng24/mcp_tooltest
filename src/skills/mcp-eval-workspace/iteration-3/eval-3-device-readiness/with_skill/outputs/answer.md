# 场景3：真机就绪判断

执行性质：主上下文读取当前Skill后的题设分析，非独立子代理运行。本场景未执行设备/API、采集或真实批次。

**不能直接运行全部车机用例，也不能把 `--mcp all` 当作只读工具清单采集。** 合成8/8只说明既定合成样本下的回放结果，不能证明真机就绪，更不能替代真实5+2用例通过。〔1〕

当前缺少两项关键输入：

1. `device_serial` 为空，尚未绑定可确认的目标设备身份。项目服务配置也明确保留空值。〔2〕
2. 完整 `tools_file` 未取得。模型工具调用需要准确的工具名、输入Schema（参数结构和约束）及必要输出定义；日志摘要不能恢复这些内容。现有L2配置只有待替换的文件路径，不等于已取得该文件或验证过模型。〔1〕〔3〕

还需核实设备二进制版本与单工具入口契约、工具/服务名称、真实参数及返回字段，评测前冻结预期错误判据，并确认初始状态、回读与恢复方法。项目当前发现/资源动作没有受验证的实时入口；配置存在或本地dry-run通过都不证明设备能力。〔1〕

`--mcp all` 可能运行已有的车窗、空调等配置测试，会有执行行为，不能用“打印了清单”证明只读采集成功或真机已准备好。注册定义dump的只读快照采集与实时tools/list也必须分开，不能互相替代。〔1〕

后续应先确认目标项目与设备、取得完整定义并冻结用例，再从确认过的最小任务逐步验证。未支持或未执行项保留 `blocked` 原因及 `unassessed` 判定，继续计入原manifest分母N，不删除以抬高通过率。本题只提供合成8/8，未给真实计划及结果，不能报出真实通过数量。〔1〕〔4〕
