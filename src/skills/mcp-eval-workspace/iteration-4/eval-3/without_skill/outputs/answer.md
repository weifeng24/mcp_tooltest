## 可行的采集方式及边界

项目提供的候选入口是 `capture-catalog`。本轮仅运行带 `--dry-run` 的离线计划。

后续实际采集前，需要确认设备所属项目、设备身份、二进制版本、实际 `dump_dir`、服务范围和读取权限。当前 `/data/mcp/dump` 来自 Ark 候选配置，不能直接假定适用于其他项目或当前设备。

该入口在真实执行时读取既有注册定义文件，不启用 dump、不重启服务、不执行工具调用。但应保留以下证据边界：

- 注册定义可能陈旧，不构成实时 `tools/list` 成功证据；多个文件不是原子快照。
- `resources_*.json` 是资源定义，不是实时资源值，不证明 `resources/read` 成功。
- `--service MCPVehicleService` 仅覆盖所选服务，不能代表全部服务的工具目录。
- 完整工具定义需要工具名和 `inputSchema`（输入参数的 JSON Schema，供参数校验及模型工具调用使用）；摘要日志不足以重建这些信息。
- 未带前缀名称生成的服务名别名仍需真实最小调用验证，不能猜测数值服务 ID。
- 后续应保留原始定义、来源设备与版本、采集方式、远端路径及内容哈希；核对后再将实际 catalog 路径用于 `tools_file`。工具部分不完整时不得宣称完整工具输入已就绪。
