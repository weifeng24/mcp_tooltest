# 场景 2：错误执行中的空调用列表

**不能证明模型正确地没有使用工具。该记录应判为 `unassessed`（无法判断），不能作为 `pass`（通过）的证据。**

## 判断依据

- `execution_status=error` 表示执行出错；`error_category=provider_error` 表示模型提供方调用链路报错，不能据此认定模型完成了任务。
- `trace_complete=false` 表示调用过程的证据不完整。`tool_calls=[]` 只能说明此列表没有记录到工具调用，不能证明模型在正常完成任务时作出了正确的不调用决定。
- 当前源码在请求模型前就初始化空的 `tool_calls` 列表；捕获提供方异常后将轨迹标为不完整并以错误结束。因此，空列表可以是尚未获得有效模型响应的结果，而非正确行为的证据。见 `src/mcp_eval/model_loop.py:73-74,79-84,103-109`。
- 当前判定器先检查执行状态和证据完整性；给定的错误状态及不完整轨迹会得到 `unassessed`。单独检查空调用列表的逻辑位于这些检查之后，不能脱离前置条件使用。见 `src/mcp_eval/judge.py:91-104,164-169`。

## 对历史 `pass` 的处理意见

历史 `verdict=pass` 与所给执行证据、当前判定逻辑不一致，不能直接采信或计为模型行为成功；也不能仅因提供方报错就判定模型行为失败。应保留原始记录，在另行复核得到的派生结论中注明“执行错误、证据不足，无法判断”。本次未修改或重建任何历史记录，也未核查产生历史标签的版本及原因。

要支持“正确地没有调用工具”，至少需要：任务本身明确要求或允许不调用工具、执行正常完成、轨迹完整、有效的最终回答及正常终止原因、调用列表确实为空，并满足用例其余判据。当前模型任务判定还要求 `stopped_reason=final_answer` 和非空最终回答，见 `src/mcp_eval/judge.py:111-117`。
