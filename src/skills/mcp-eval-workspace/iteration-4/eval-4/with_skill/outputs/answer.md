# 场景 4：N02 越界参数返回成功的判定

## 结论

**N02 应判为 `fail`（失败），属于被测工具对非法参数的处理不符合已确认规范。**

本结论以题设为依据：工具允许温度为 16—30 度，N02 实际传入 40，且成功响应与该真实请求的关联证据完整。40 超出允许范围，服务却返回成功，已经构成明确的预期违背。不能因服务返回“成功”而将负面用例判为通过，也不应在题设证据完整的条件下改判 `unassessed`（无法判断）。

## 判定依据

| 核对项 | 题设事实与判定意义 |
|---|---|
| 有效范围 | 已确认规范为 16—30 度；40 > 30，属于越界输入。 |
| 负面用例预期 | 应拒绝越界输入，并符合预先定义的参数错误类型或原因；收到成功响应不满足该预期。题设未给出具体错误码，不能补造。 |
| 请求与响应关联 | 题设已确认真实请求关联完整，因此这里不是响应缺失、错配或证据不足的问题。 |
| 状态规则 | `references/report-guide.md` 第 4 条规定：完整证据确认不符合预期应判 `fail`；`pass` 要求全部断言及后置条件通过。 |
| 预期冻结 | 同文件第 7 条规定：负面用例必须匹配预定义错误类型或原因，不能根据实际结果倒改业务预期。不能为迁就成功响应，将范围扩大到 40 或临时改成“自动截断即通过”。 |

## 问题归属与结论边界

- 可确认的是：该请求下，服务对越界温度返回成功，违反已确认的工具输入规范，负面用例失败。
- 根因仍需区分参数范围校验缺失、错误映射异常等可能性；仅凭题设不能确定具体实现缺陷。
- “返回成功”不等于已证明设备实际设置到了 40 度，也不能据此推断发生了自动截断、设备损坏或其他状态变化。
- 该结论针对 N02 的工具接口行为；题设不足以评价模型选择工具的能力或 IDE／客户端表现，也不代表整批评测已完成。
