# 历史记录判定复核

## 结论

**不能证明模型正确地没有使用工具。** 对“应当不调用工具”的行为评测，该记录应按 `unassessed`（无法判断）处理，不能依据历史 `verdict=pass` 认定通过；现有证据也不足以认定模型行为失败。

仅就用户提供的这一条记录，复核口径为：通过 0、行为失败 0、无法判断 1。批次路径、计划总数和其他执行项未提供，不能计算批次通过率或判定覆盖率。

## 依据

| 字段 | 能支持的事实及限制 |
|---|---|
| `execution_status=error` | 记录标记执行出错，不能据此认定模型完成了目标任务。执行错误与模型行为判定须分开。 |
| `error_category=provider_error` | 记录将错误归类为模型提供方接入或请求错误；不能将其作为模型正确选择不调用工具的证据。具体原因和发生阶段尚不明确。 |
| `tool_calls=[]` | 当前记录中的工具调用列表为空，仅说明没有记录到调用；不能区分主动不调用、请求失败导致未进入决策阶段或记录缺失。 |
| `trace_complete=false` | 调用轨迹不完整，不能证明整个执行过程没有工具调用。 |
| `verdict=pass` | 属于历史判定标签，不是独立行为证据；与上述执行错误及证据缺失存在冲突，需复核判定依据。 |

适用规则：`src/skills/mcp-eval/SKILL.md` 明确禁止将 API 失败或轨迹缺失时的“没看到调用”解释为“正确不调用”；`references/report-guide.md` 第 4、9 条规定证据不足归为 `unassessed`，负面用例必须匹配预先定义的预期，不能把其他错误算作通过；`references/troubleshooting.md` 明确说明 `provider_error` 不能满足“正确不调用”用例。

若后续完整证据确认存在被禁止的调用，应判为行为失败，后续提供方错误不能撤销已观察到的违规。本次没有这类证据。
