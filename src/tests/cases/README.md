# 评测用例设计

状态：用例面向公司车载 `mcp_service` 的 8 个服务设计，基于 2026-10-13 只读核实的协议与测试文档（`MCP_Agent.md` §9、`TEST_GUIDE.md`、`test_config_ark.json`）。**预期行为标注“待真机校准”的，以首次上机实测为准修正**；修正过程本身作为评测发现记录。

## 1. 正向用例（L1，≥5）

| 编号 | 场景 | 预期行为 | 断言要点 |
|---|---|---|---|
| P01 | tools/list 枚举（MCPVehicleService） | 返回完整工具列表，每个工具含 name/description/inputSchema/outputSchema | 工具名带 serviceId 前缀；schema 为合法 JSON Schema；关键工具（如 setTemp）存在 |
| P02 | 合法参数调用（如 HvacService.setTemp，temperature=22） | 返回 success=true | 响应符合 outputSchema；随后 getTemp 回读一致（状态类工具交叉验证） |
| P03 | 边界值（setTemp=16 与 30，schema 标注 minimum/maximum） | 两者均被接受 | 边界不被误拒；回读值正确 |
| P04 | 多服务路由（不同 serviceId 前缀的工具各调一次） | RouteManager 正确路由到对应服务 | 各服务响应内容与各自领域一致，无串扰 |
| P05 | resources/list＋resources/read（如 dds://Hvac_Status_topic） | 资源枚举完整；读取返回数据 | uri 格式正确；read 响应非空且结构符合预期（待真机校准） |

## 2. 负面控制（L1，2 条）

| 编号 | 场景 | 预期行为 | 断言要点 |
|---|---|---|---|
| N01 | 调用不存在的工具名（如 `HvacService.noSuchTool`） | 返回明确错误，不静默成功 | 错误类别可诊断；服务本身不崩溃，后续正常调用仍可用 |
| N02 | 参数越界（setTemp=40，超出 schema 16—30） | 被拒绝并返回参数错误（待真机校准：也可能被服务端静默截断或接受——任一实际行为都如实记录为评测发现） | 实际行为与 schema 声明的一致性；错误信息是否可操作 |

## 3. 补充边界用例（L1，时间允许时执行）

| 编号 | 场景 | 检查目标 |
|---|---|---|
| E01 | 缺少必填参数（setTemp 不传 temperature） | 参数校验行为与错误可诊断性 |
| E02 | 服务未就绪时调用（启停间隙） | 错误类别为连接/可用性，而非业务错误 |
| E03 | 连续快速调用同一状态工具 | 无状态错乱；响应顺序正确 |

## 4. 模型级用例（L2，双模型各执行）

| 编号 | 任务（自然语言） | 预期模型行为 |
|---|---|---|
| M01 | “把空调温度调到 22 度” | 选择 setTemp、参数 temperature=22；执行后回读验证；调用轮数 ≤3 |
| M02 | “现在空调温度是多少？” | 选择 getTemp（无参）；如实转述返回值 |
| M03（负面控制） | “帮我写一首关于夏天的诗”（与工具无关） | 不调用任何工具，直接回答 |
| M04（负面控制） | “把温度调到舒服的程度”（缺少确定值且无法从上下文补齐） | 先澄清或给出合理默认并说明；不盲目编造参数（预期口径评测前与导师对齐） |

## 5. 用例数据规范

- 每条用例一个 JSON 文件：`case_id`、层次、类别、服务/工具、参数或任务文本、断言、预期来源（文档/真机校准）、超时。
- 真机预期以首次上机实测校准；校准差异（文档预期 vs 实际行为）记入评测发现。
- 用例数量按独立 `case_id` 计；双模型重复执行不增加用例数。
